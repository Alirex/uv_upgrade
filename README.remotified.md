# uv-upx

[![CI](https://github.com/Alirex/uv_upgrade/actions/workflows/ci.yml/badge.svg)](https://github.com/Alirex/uv_upgrade/actions/workflows/ci.yml)
[![PyPI version](https://img.shields.io/pypi/v/uv-upx)](https://pypi.org/project/uv-upx/)
[![Python versions](https://img.shields.io/pypi/pyversions/uv-upx)](https://pypi.org/project/uv-upx/)
[![License](https://img.shields.io/pypi/l/uv-upx)](https://github.com/Alirex/uv_upgrade/blob/v0.5.0/LICENSE.txt)

Upgrade the dependency constraints in the `pyproject.toml` files of a uv project or workspace to the versions `uv`
locks.

Before, with `pydantic` 2.12.5 and `tomlkit` 0.13.3 available:

```toml
dependencies = [
    "pydantic>=2.10.0",
    "tomlkit>=0.12.0,<1",
    "typer",
]
```

After `uv-upgrade`:

```toml
dependencies = [
    "pydantic>=2.12.5",
    "tomlkit>=0.13.3,<1",
    "typer>=0.20.1",
]
```

## Install

Needs [uv](https://docs.astral.sh/uv/getting-started/installation/). Run it from any directory except the project
directory; it installs or upgrades the tool:

```shell
if ! command -v uv-upx &> /dev/null; then
    uv tool install uv-upx
else
    uv tool upgrade uv-upx
fi

uv-upgrade --version
```

Or run it without installing:

```shell
uvx uv-upx
```

Or the short command with uvx:

```shell
uvx --from uv-upx uv-upgrade
```

Note: `uvx uv-upgrade` (without `--from uv-upx`) runs a different package, [uv-upgrade](https://pypi.org/project/uv-upgrade/), not this one.

Check that it is installed: `uv tool list --show-python`. Remove it with all data: `uv tool uninstall uv-upx`.

Dev installation: [see here](https://github.com/Alirex/uv_upgrade/blob/v0.5.0/docs_extra/dev.md#install-app-system-wide-in-development-mode).

## Usage

Run it in the folder with the `pyproject.toml` (the project or workspace root):

```shell
uv-upgrade
```

or

```shell
uv-upx upgrade run
```

It is the same. But `uv-upx` provides more features.

The common cases:

- `>=` constraints move to the locked version; `==`, `<`, `<=`, `~=` and other upper bounds are left alone.
- A dependency without a constraint gets `>=<locked version>`; `--keep-unconstrained` leaves it alone.
- `--profile with_pinned` also upgrades `==` pins; `--interactive` asks to accept or reject each change.

Comments and formatting in `pyproject.toml` are kept, and a failed run rolls back `pyproject.toml` and `uv.lock`. Every
rule, with examples: [behaviour](https://github.com/Alirex/uv_upgrade/blob/v0.5.0/docs_extra/behaviour.md).

## Install CLI completion (Optional)

This will install completion for the current shell. Available after restarting the shell.

for `uv-upgrade`:

```shell
uv-upgrade --install-completion
```

for `uv-upx`:

```shell
uv-upx --install-completion
```

Note: relatively safe to run multiple times. It just adds extra newlines to your shell config when run multiple times.
